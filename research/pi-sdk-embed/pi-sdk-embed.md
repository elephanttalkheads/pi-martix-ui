Primary sources read: `package.json`, `README.md`, `docs/sdk.md` (full), `docs/extensions.md` (relevant parts), `docs/session-format.md` (full), `docs/compaction.md` (full), all 13 files in `examples/sdk/` (01-minimal.ts … 13-session-runtime.ts + README.md). Cross-checked against upstream source at `github.com/earendil-works/pi` tag `v0.84.1` (`packages/coding-agent/src/core/agent-session.ts`, `packages/agent/src/types.ts`) and the real-world Electron embedding `tbrandenburg/pi-desktop` (which wraps this SDK in an Electron main process).

## Summary

The pi SDK is embeddable in an Electron main process: it is ESM-only, pure JS (no native modules; `photon-node` is WASM), and declares `engines.node >= 22.19.0`, which maps to Electron ≥ 37.6.x or ≥ 39 (Electron 38 bundles Node 22.18.0, below the floor). It ships a complete, typed event stream (`AgentSessionEvent` union, ~24 event types) covering text/thinking deltas, tool call lifecycle, turn/agent lifecycle, queue, retry, and compaction — enough to drive a rich live UI, as proven by pi-desktop. Sessions are JSONL on disk with a tree structure and are fully resumable; config (settings.json, models.json, auth.json under `~/.pi/agent`) is reused automatically by `ModelRuntime`/`SettingsManager`/`DefaultResourceLoader` unless overridden. Multi-session is supported via per-session `SessionManager` plus `createAgentSessionRuntime()`/`AgentSessionRuntime` for new/resume/fork/import replacement flows. Main pitfalls for a long-lived host: `prompt()` never throws on provider failures (must inspect `stopReason`/`errorMessage`), auto-compaction and retries run behind the scenes and need UI surfacing, `ctx.ui` is headless unless you implement an `ExtensionUIContext`, and `ModelRuntime` catalog refresh can hang (use `allowModelNetwork: false` + abort signals).

## Findings

### 1. Node version & Electron main-process fit
- `package.json` declares `"engines": { "node": ">=22.19.0" }` and `"type": "module"` — the package is ESM-only; `main`/`exports["."]` point at `dist/index.js` (+ `dist/index.d.ts`). Extra entry points: `./rpc-entry` and `./client`. [package.json — engines, type, exports]
- The Node floor is enforced in practice, not just advisory: upstream issue #4876 ("pi update silently stays on 0.74.1 under Node 20 due to Node >=22.19 requirement"). [https://github.com/earendil-works/pi/issues/4876]
- Electron↔Node mapping: Electron 37.6.x bundles Node 22.19.0; **Electron 38 bundles Node 22.18.0 — below the floor**; Electron 39 bundles Node 22.20.0; Electron 40 bundles Node 24.11.1. Recommend Electron ≥ 39 (or ≥ 37.6.x if pinned). Electron ESM support in the main process is stable (since Electron 28). [https://releases.electronjs.org/release?channel=stable&major=v37, https://github.com/electron/electron/releases/tag/v38.0.0, v39.0.0, v40.0.0]
- No native modules in the dependency tree that would force `electron-rebuild`: `@silvia-odwyer/photon-node` is a WASM addon; jiti/undici/proper-lockfile/cross-spawn are pure JS. Severity: low risk.
- Proven precedent: `tbrandenburg/pi-desktop` runs the pi agent SDK in the Electron main process with a sandboxed React renderer (preload IPC bridge; credentials never leave main). It pins `node >= 22.19` and Electron 43. [https://github.com/tbrandenburg/pi-desktop]

### 2. Complete AgentSessionEvent model for a live UI
Events are delivered via `session.subscribe(listener: (event: AgentSessionEvent) => void): () => void` (unsubscribe). The union (verified against the exhaustive switch in pi-desktop's `runtime.ts` and upstream `agent-session.ts`/`agent/types.ts`):

**Streaming text** — `message_update { message, assistantMessageEvent }`, where `assistantMessageEvent.type` is `"text_delta"` (delta text) or `"thinking_delta"` (reasoning tokens when thinking enabled). Finalized text arrives via `message_end { message }` (full `AssistantMessage` with `usage`, `stopReason`, `errorMessage?`). [docs/sdk.md; upstream agent/types.ts]

**Tool calls** — `tool_execution_start { toolCallId, toolName, args }` → `tool_execution_update { toolCallId, toolName, args, partialResult }` (streaming tool output) → `tool_execution_end { toolCallId, toolName, result, isError }`. Parallel tool execution: starts preflight in assistant source order, ends in completion order; tool-result *messages* are emitted later in source order. Durations are not surfaced — the UI computes them itself. `bash_execution_update` streams user `!cmd` bash output. [docs/sdk.md; docs/extensions.md tool events; pi-desktop runtime.ts]

**Message lifecycle** — `message_start { message }`, `message_end { message }` (fired for user, assistant, and toolResult messages). [upstream agent/types.ts]

**Agent lifecycle** — `agent_start`, `agent_end { messages }` (new messages from the run; usage comes from the last assistant message), `agent_settled` (fired after retries/compaction/follow-ups are all done — the reliable "idle" signal). [docs/sdk.md; docs/extensions.md]

**Turn lifecycle** — `turn_start`, `turn_end { message, toolResults }` (one LLM response + its tool calls). [upstream agent/types.ts]

**Queue / session / retry / compaction** — `queue_update { steering, followUp }` (queue lengths), `entry_appended`, `session_info_changed`, `thinking_level_changed`, `auto_retry_start { attempt, maxAttempts }`, `auto_retry_end`, `compaction_start`, `compaction_end`, `summarization_retry_scheduled`, `summarization_retry_attempt_start`, `summarization_retry_finished`. [docs/sdk.md; pi-desktop runtime.ts exhaustive switch]

These are exactly the 24 event types a chat UI needs: deltas → streaming bubbles, tool start/end → tool rows, agent_end → usage/cost footer, auto_retry_start → retry badge, compaction events → status line.

### 3. Multi-session support
- **Per-session persistence manager**: `SessionManager.create(cwd, sessionDir?)` / `.inMemory(cwd?)` / `.open(path)` / `.continueRecent(cwd)` / `.list(cwd)` / `.listAll()` / `.forkFrom(sourcePath, targetCwd)`. Each `createAgentSession({ sessionManager })` yields an independent `AgentSession` (own `agent`, queue, messages, compaction). [docs/sdk.md; examples/sdk/11-sessions.ts]
- **Session replacement** (the `/new`, `/resume`, `/fork`, `/clone`, `/import` flows): `createAgentSessionRuntime(factory, { cwd, agentDir, sessionManager })` returns an `AgentSessionRuntime` with `newSession()`, `switchSession(path)`, `fork(entryId, { position: "before" | "at" })`, `importFromJsonl()`, and `runtime.session` which *changes* after each operation. **Critical**: event subscriptions are bound to a specific `AgentSession` — re-subscribe and re-call `session.bindExtensions(...)` after every replacement. `runtime.diagnostics` carries creation diagnostics. [docs/sdk.md; examples/sdk/13-session-runtime.ts]
- pi-desktop maps renderer conversation IDs to stable session files via `SessionManager.create(cwd, undefined, { id: conversationId })` + `SessionManager.list(cwd)` lookups — a good pattern for desktop "conversation" identity. [pi-desktop runtime.ts]
- Concurrent live sessions in one process are not explicitly documented/guaranteed; each `AgentSession` is independent, but a shared `ModelRuntime` and any process-global extension state are shared — validate before running N sessions in parallel (see Gaps).

### 4. Session persistence, file format, resume
- **Location**: `~/.pi/agent/sessions/--<encoded cwd>--/<timestamp>_<uuid>.jsonl` (cwd with `/` → `-`). Overridable via `SessionManager.create(cwd, customDir)` or env `PI_CODING_AGENT_DIR` / `PI_CODING_AGENT_SESSION_DIR`. Deleting = removing the file. [docs/session-format.md]
- **Format**: JSONL, header line `{"type":"session","version":3,"id","timestamp","cwd","parentSession"?}`; subsequent lines are tree entries with `id`/`parentId` (`message`, `model_change`, `thinking_level_change`, `compaction`, `branch_summary`, `custom`, `custom_message`, `label`, `session_info`). Older v1/v2 files auto-migrate to v3 on load. Messages embed `AgentMessage` objects (user/assistant/toolResult/bashExecution/custom/branchSummary/compactionSummary roles; content blocks text/image/thinking/toolCall). [docs/session-format.md]
- **Compaction entries** are checkpoints: `summary`, `firstKeptEntryId` (legacy) or self-contained `retainedTail` (AgentMessage[] kept after compaction) so context can rebuild without walking older entries. [docs/session-format.md; docs/compaction.md]
- **Resume**: `SessionManager.continueRecent(cwd)` (most recent or new, returns `modelFallbackMessage` if the stored model can't be restored), `SessionManager.open(path)`, `SessionManager.list(cwd)`/`listAll()` for pickers, `AgentSessionRuntime.switchSession()`/`importFromJsonl()` for in-app switching. Model is restored from the session file first; settings default; first available fallback. [docs/sdk.md; examples/sdk/11-sessions.ts]

### 5. Provider config / API keys / model resolution in embedded mode
- **Yes — `~/.pi/agent` is reused automatically.** `ModelRuntime.create()` (default) loads credentials from `~/.pi/agent/auth.json` and custom models from `~/.pi/agent/models.json`; `SettingsManager.create()` merges global `~/.pi/agent/settings.json` + project `<cwd>/.pi/settings.json` (project overrides global, nested keys merge); `DefaultResourceLoader` defaults to `agentDir: getAgentDir()` (≈ `~/.pi/agent`, honors `PI_CODING_AGENT_DIR`). All can be overridden with custom paths for app-owned config. [docs/sdk.md Options Reference; examples/sdk/09, 10, 12]
- **Auth resolution priority** (ModelRuntime): (1) runtime overrides via `setRuntimeApiKey()` (not persisted), (2) stored `auth.json` (API keys or OAuth tokens), (3) env vars (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, …), (4) fallback resolver for custom provider keys. [docs/sdk.md API Keys and OAuth]
- **Model selection when none passed**: restore from session → settings default → first available. Helpers `resolveCliModel()` and `resolveModelScopeWithDiagnostics()` mirror CLI `--model` / `--models` semantics. `scopedModels`/`enabledModels` restrict model cycling. [docs/sdk.md Model]
- **Desktop-specific caution (learned from pi-desktop)**: `ModelRuntime.create()` may attempt remote catalog refresh that can hang for seconds on exotic providers — pi-desktop passes `allowModelNetwork: false` and registers its own provider. `setRuntimeApiKey()` internally calls `refresh()` and was observed to hang against a `streamSimple`-only provider; pi-desktop instead injects credentials via `registerProvider(providerId, { apiKey })`. [pi-desktop runtime.ts comments]

### 6. Skills / extensions / prompt templates / context files loading
- `createAgentSession()` uses a `ResourceLoader`; default is `DefaultResourceLoader` (`cwd` + `agentDir`), overridable wholesale with a custom `ResourceLoader` (see examples/sdk/12-full-control.ts) or partially via overrides: `systemPromptOverride`, `appendSystemPromptOverride`, `skillsOverride`, `promptsOverride`, `agentsFilesOverride`, `additionalExtensionPaths`, `extensionFactories`, `eventBus`. All override hooks return `{ ...current, diagnostics }`. [docs/sdk.md ResourceLoader/Extensions/Skills/Slash Commands/Context Files; examples 03, 04, 06, 07, 08]
- **Discovery locations**: extensions from `~/.pi/agent/extensions/` + `<cwd>/.pi/extensions/` + `settings.json` `extensions`/`packages` arrays; skills from `.pi/skills/`, `.agents/skills/` (cwd and ancestors to git root), `~/.pi/agent/skills/`, `~/.agents/skills/`; prompts from `.pi/prompts/` + `~/.pi/agent/prompts/`; context files = `AGENTS.md`/`CLAUDE.md` walking up from cwd + global `~/.pi/agent/AGENTS.md` (+ `AGENTS.override.md` substitution). Extensions are TS loaded via jiti (no compile step) and can register tools/commands/providers, block tool calls, inject messages, customize compaction. [docs/extensions.md; README Context Files; examples/sdk/06-extensions.ts]
- **Project trust behavior** (critical for a desktop app): project-local `.pi/extensions` (and project settings/packages) load **only after the project is trusted**. Trust resolution: `project_trust` extension event (user/global extensions only; a handler can return `{ trusted: "yes"|"no", remember? }` and own the decision) → saved `~/.pi/agent/trust.json` decisions → `defaultProjectTrust` setting (`ask`/`always`/`never`). **Non-interactive modes never show a prompt**: `ask` (default) and `never` *ignore* project resources, `always` loads them. An embedded host must therefore either set `defaultProjectTrust` explicitly or implement a `project_trust` handler with its own UI; extensions can check `ctx.isProjectTrusted()`. [docs/extensions.md project_trust; README Project Trust]
- **Extension UI is headless by default**: `hasUI` is false until `session.bindExtensions({ uiContext, mode: "rpc" })` is called; pi-desktop implements an `ExtensionUIContext` over IPC to React modals (`select`/`confirm`/`input`/`notify` work; TUI-only methods are no-ops), modeled on pi's own `"rpc"` mode. Without this, extensions calling `ctx.ui.confirm/select/input` get no interaction. [pi-desktop ui-context.ts, runtime.ts]

### 7. Constraints & pitfalls for a long-lived desktop host
Severity-flagged; "medium+" items are things a UI integration must handle.

1. **`session.prompt()` never throws for provider/request/runtime failures** (high). A failed turn resolves normally with a final assistant message `stopReason: "error" | "aborted"` + `errorMessage`. pi-desktop checks `session.messages.at(-1)` after `prompt()` to distinguish real errors. Exceptions only throw for pre-request failures (e.g., credential resolution). [pi-desktop runtime.ts; upstream agent/types.ts StreamFn contract]
2. **Abort semantics** (high): `session.abort()` aborts the current operation; wire your UI cancel button to it (pi-desktop: `signal.addEventListener("abort", () => session.abort())`). Aborts produce `stopReason: "aborted"`. Extension handlers receive `ctx.signal` for abort-aware nested work. `agent_settled` is the true idle event (retries + compaction retries + queued follow-ups included). [docs/sdk.md; docs/extensions.md]
3. **steer vs followUp vs streaming prompt** (high): during streaming, `session.prompt()` **throws unless** `{ streamingBehavior: "steer" | "followUp" }` is passed; `session.steer(text)` delivers after the current turn's tool calls (interrupt-style), `session.followUp(text)` after the agent finishes. `queue_update { steering, followUp }` reports pending queue lengths; Esc/abort restores queued messages in the TUI. UI must expose both delivery modes (Enter vs Alt+Enter) and reflect the queue. [docs/sdk.md Prompting; README Message Queue]
4. **Compaction runs automatically** (high): auto-compaction triggers at `contextTokens > contextWindow - reserveTokens` (default reserve 16384) with `keepRecentTokens` 20000; reasons `"threshold"`, `"overflow"` (with turn retry, `willRetry`), or `"manual"`. It's lossy for context but full history stays in the JSONL (`/tree`-recoverable). Control via settings `compaction: { enabled, reserveTokens, keepRecentTokens }`, `session.compact(customInstructions?)`, `session.abortCompaction()`, or extension `session_before_compact` (cancel/custom summary). A long-lived host must surface `compaction_start`/`compaction_end` and the context-usage drift (`ctx.getContextUsage()`, or compute from `session.agent.state.messages`). [docs/compaction.md; docs/sdk.md; docs/extensions.md]
5. **Memory behavior** (medium): `session.agent.state` holds `messages`, `model`, `thinkingLevel`, `tools`, `streamingMessage`, `errorMessage`; assignment copies top-level arrays (safe to replace for branching/restore). Compaction replaces the context but `session.messages` still reflects post-compaction state via rebuilt context. Long-lived hosts should `dispose()` sessions they abandon and re-bind subscriptions after `AgentSessionRuntime` replacements. Settings writes are async — call `settingsManager.flush()` before exit and surface `drainErrors()`. [docs/sdk.md; examples/sdk/10-settings.ts; upstream agent/types.ts AgentState]
6. **`ctx.ui` is unavailable/no-op without a custom `ExtensionUIContext`** (medium) — see finding 6. Extension dialogs (`select`/`confirm`/`input`) must be bridged to your own UI or extensions will hang/no-op.
7. **Security boundary** (high): extensions and skills execute arbitrary code with full user permissions (`bash` tool runs shell commands). Keep the SDK in the main process and never expose Node/credentials to the renderer; treat project trust as a real gate. [docs/extensions.md Security note; pi-desktop README]
8. **Output/context limits** (low): built-in tools truncate output at 50KB / 2000 lines; compaction summarization serializes tool results truncated to 2000 chars. Bash tool injects `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, `PI_REASONING_LEVEL` env vars into child processes (disable with `exposeSessionEnvironment: false`). [docs/extensions.md; README]
9. **Startup network ops** (low): model catalog refresh and update/telemetry pings can touch the network (`PI_OFFLINE=1`, `PI_SKIP_VERSION_CHECK=1`, `enableInstallTelemetry: false`); pass `AbortSignal.timeout(...)` to `ModelRuntime.refresh()`. [README; docs/sdk.md]

## Gaps
- **Concurrent live sessions**: nothing in the docs explicitly guarantees multiple simultaneous `AgentSession` instances in one process (shared `ModelRuntime` + process-global package/extension state). Verify with a 2-session soak test before building a multi-chat-tab desktop UI.
- **Exact `message_update` inner union beyond text_delta/thinking_delta**: `AssistantMessageEvent` (pi-ai) may include `done`/`error`/tool-call inner events; the SDK doc only shows the two delta types and message_end carries finalization. Inspect `node_modules/@earendil-works/pi-ai/dist/` types to be exhaustive.
- **Runtime Node-version enforcement point**: engines + CLI behavior confirm the floor; whether `dist/index.js` itself throws (vs. npm warning) is unverified — either way, bundle/pin Node ≥ 22.19 in the app.
- **Electron 38 (Node 22.18.0) is below the floor** — do not ship on it.
- **Trust UX**: `defaultProjectTrust: "ask"` in a headless desktop host silently ignores project resources; decide app-level trust policy explicitly.

## Feasibility summary (~15 lines)
- **Embeddable in Electron?** Yes. ESM-only, pure-JS package, no electron-rebuild needed; requires Node ≥ 22.19.0 → Electron ≥ 39 (or 37.6.x); Electron 38 is below the floor. Proven by pi-desktop (SDK in main process, sandboxed renderer).
- **Event richness for UI:** Excellent — 24 typed events: text/thinking deltas, tool start/update/end (parallel-aware), message/turn/agent lifecycle, queue_update, auto-retry, compaction, agent_settled idle signal; usage from agent_end.
- **Multi-session:** Per-session SessionManager + AgentSessionRuntime for new/resume/fork/import; must re-subscribe and re-bindExtensions after every session replacement; concurrent-session safety unverified.
- **Config reuse:** Automatic — ModelRuntime reuses ~/.pi/agent/auth.json + models.json; SettingsManager merges global+project settings.json; DefaultResourceLoader discovers extensions/skills/prompts/AGENTS.md; auth priority runtime-key → auth.json → env.
- **Top pitfalls:** prompt() never throws on provider errors (check stopReason/errorMessage); steer vs followUp vs streaming prompt rules; auto-compaction is on by default and must be surfaced; ctx.ui is headless until you wire an ExtensionUIContext; ModelRuntime catalog refresh can hang (allowModelNetwork:false + timeouts); project trust must be handled explicitly; extensions are arbitrary code — keep them in the main process.
