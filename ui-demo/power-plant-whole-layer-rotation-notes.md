# Power Plant 整层旋转原型

> 状态：一次性 UI / 机械运动原型，不是生产实现。它只回答“怎样让会话切换看起来像整层 Power Plant 在旋转”；正式迁移目标仍是 `deepseek-zion`。

入口：[power-plant-whole-layer-rotation-prototype.html](./power-plant-whole-layer-rotation-prototype.html)。文件使用纯本地 HTML、CSS、SVG 和原生 JavaScript，双击即可运行。

## 要回答的问题

旧原型将 `rotateY(...) translateZ(...)` 分别施加给培育仓，而 Power Plant 墙体是一个不参与变换的静态兄弟节点。结果即使仓体具备纵深位移，画面仍会被理解为“培育仓在静止墙前转动”。

本原型验证：把一层 Power Plant 拆成固定纵向主轴与可旋转项目转环，并让墙段、机械接口和培育仓组成刚性盘位总成，能否让会话切换获得“整个项目层在墙内绕竖轴旋转”的机械语义。

## 已确认的领域模型

- **项目转环**：与一个工作区对应、可绕建筑内部竖直主轴独立旋转的完整环层。
- **盘位总成**：由旋转装甲墙段、机械接口或管线、培育仓盘位组成的刚性重复单元。
- **固定纵向主轴**：贯穿多个工作区的承重建筑结构，不参与项目转环的会话切换。
- 一个培育仓盘位可以为空；只有被真实会话占用的盘位才称为会话培育仓。

术语已经同步到根目录 `CONTEXT.md`。

## 结构答案

```text
project-layer                       固定项目层位置
├─ fixed-bearing                    静态轴承、窗口前缘与纵向主轴
├─ layer-rotor                      唯一共享 ringRotation
│  ├─ slot-frame[0]                 固定安装角 0°
│  │  └─ 墙段 + 机械接口 + 培育仓
│  ├─ slot-frame[1]                 固定安装角 30°
│  │  └─ 墙段 + 机械接口 + 培育仓
│  └─ ...共 12 个
└─ foreground-mask                 静态前景遮挡与深度投影
```

角度只有两层来源：

```text
盘位固定安装角 = slotIndex × 30°
盘位最终角度   = 固定安装角 + 项目转环共享 ringRotation
```

`layer-rotor` 是唯一接收切换累计角的节点。盘位总成内部不得为墙段、接口和培育仓分别计算旋转动画。

## 为什么整层旋转可以被看见

原型同时使用四类证据：

1. 装甲墙段的接缝、编号、铆钉和轴承齿随项目转环移动；
2. 墙段与培育仓在斜视角产生同向透视压缩；
3. 总成转入固定纵向主轴时被机械窗口前缘逐步遮挡；
4. 机械接口灯、墙段亮度和培育仓投影保持刚性相对关系。

不绘制完整圆盘或椭圆轨道。项目转环通过矩形装甲墙段、窗口遮挡和局部轴承结构成立。

## 默认观察形态与校验模式

使用 URL 参数切换，`←` / `→` 也可循环切换：

| URL | 名称 | 用途 |
| --- | --- | --- |
| `?variant=A` | 装甲窗口 | 备选镜头；验证固定窗口遮挡下是否仍能读出墙内旋转 |
| `?variant=B` | 轴承剖面（默认） | 最终视觉与素材基线；减少静态外壳遮挡，直接显露局部轴承、墙段、接口和培育仓的刚性关系 |
| `?variant=C` | 运动校验 | 使用半透明主轴和网格基准排查错误的独立变换 |

三种模式不是三个旋转方案；它们观察同一个已确认的项目转环结构。B 已从单纯诊断模式升级为默认视觉基线，A 与 C 保留为结构校验镜头。

## 尺寸与密度

```text
侧栏总宽                  280px
固定纵向主轴               27px
项目转环局部可见装甲       约 43px
机械接口                   31px（与装甲部分重叠安装）
临时培育仓主体             178 × 58px
盘位总成外框               232 × 68px
环带半径                   66px
每层物理盘位               12
相邻盘位角度               30°
完整细节培育仓             正面附近 5 个
```

静态纵向主轴仍保持此前缩小后的 `27px`。旋转装甲只在对应项目层的机械窗口中局部外凸，不恢复成贯穿侧栏的宽墙。

## 会话切换状态模型

每个工作区独立保存：

```js
{
  activeIndex,       // 已锁定会话
  targetIndex,       // 最新目标会话
  rotation,          // 已锁定共享角度
  targetRotation,    // 最新目标共享角度
  motion             // locked | unlocking | rotating | settling
}
```

- 点击指定会话时选择等价角度中的最短路径；
- 上一个/下一个保持操作方向，首尾切换继续沿环向经过空盘位；
- 动画期间再次输入时取消旧计时，只保留最新目标，并从当前 CSS 过渡位置平滑改道；
- 切换工作区只改变操作焦点，不重置其他项目转环角度。

默认编舞：

```text
0–90ms      轴承解锁
90–610ms    项目转环旋转至目标外约 1.2°
610–760ms   回弹并锁定目标角度
```

`prefers-reduced-motion` 下取消解锁、长距离编舞和回弹，使用约 `160ms` 的直接角度与明暗交接。

## Demo 数据边界

- 页面包含三个明确标记的 Demo 工作区，用于验证独立项目转环状态；
- 每层固定 12 个物理盘位，真实 Demo 会话只占用前几个盘位；
- 其余结构明确显示为 `EMPTY BAY`，不伪造会话、进度或遥测；
- 页面状态只存在内存，不持久化，也不连接项目业务状态。

1. 先生成一张透明背景的完整盘位总成概念图，统一墙段、机械接口与培育仓的连接截面、光源、透视和漫画笔触；

3. 首轮不生成 `-60° / -30° / +30° / +60°`，角度变体在三张正视素材验收通过后再决定。

## 原型判断标准

在 A 模式执行至少三次连续会话切换，并检查：

- 首先注意到移动的是墙段接缝和接口，而不是只有红色培育仓；
- 墙段、接口、仓体之间没有相位差、拉伸或相对滑动；
- 转入墙内的总成被静态窗口遮挡，而非缩小后凭空消失；
- 分别操作三个工作区后，各层保持不同角度；
- 快速连续输入最终锁定最新会话，没有积压动作；
- Reduced 模式仍能通过墙段与培育仓共同换位理解为整层切换。

若 A 模式仍被理解为“培育仓轮播”，先增强移动墙段的可见宽度、接缝对比和窗口遮挡，不应首先增加仓体旋转幅度。
