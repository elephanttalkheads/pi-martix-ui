# Power Plant 培育仓盘位角度实验

> 状态：一次性逻辑原型。它只用于选择仓间角度，不是生产实现；正式迁移目标仍是 `deepseek-zion`。

## 实验问题

在固定 `280px` 侧栏、固定 `88px` 环带半径、固定 `220 × 76px` 仓体外框与固定透视下，每层培育仓盘位容量如何改变：

- 相邻盘位的角度；
- 侧栏视域内同时出现的盘位数量；
- Power Plant 的巨构尺度感；
- 每次切换真实会话的运动力度。

入口：[power-plant-bay-angle-lab-prototype.html](./power-plant-bay-angle-lab-prototype.html)。文件内嵌实际仓体缩略素材，不需要开发服务器，双击即可运行。

## 领域区分

- **培育仓盘位**：Power Plant 环带的物理容量，可以为空。
- **会话培育仓**：被一个真实会话占用的盘位。
- 原型固定使用 5 条显式 Demo 会话；改变容量只增减空盘位，不创造会话。
- Power Plant 的一层称为“项目层”，不用“工作区层”。

词汇已经同步到根目录 `CONTEXT.md`。

## 纯状态模型

页面中的 `RingGeometry` 是独立于 DOM 的纯模块。原型状态为：

```js
{
  bayCount,       // 6–36 的整数物理盘位容量
  activeSession,  // 当前真实会话
  rotationSteps,  // 累计旋转的盘位步数
  material,       // actual | schematic
  lastAction
}
```

派生规则：

```text
仓间角度 = 360° / bayCount
当前环带角度 = -rotationSteps × 仓间角度
可见盘位 = 盘位中心角处于 -80°～80°
单次会话切换 = rotationSteps ± 1
```

当前会话固定在正面；其余四条真实会话按原顺序占据前方连续盘位。容量改变时使用短暂淡出重排，不播放会话切换动画。

## 推荐预设

| 方案 | 每层盘位 | 仓间角度 | 约可见盘位 | 要验证的取舍 |
| --- | ---: | ---: | ---: | --- |
| 戏剧化 | 6 | 60° | 3 | 切换最强，但建筑容量最小 |
| — | 8 | 45° | 3 | 强切换、完整闭环 |
| 暂定 | 12 | 30° | 5 | 当前候选：明确切换与适中容量 |
| 平衡参考 | 18 | 20° | 9 | 动作力度与巨构密度的折中 |
| — | 24 | 15° | 11 | 更密集、更像基础设施 |
| 巨构密集 | 36 | 10° | 17 | 最大规模，但单步可能不明显 |

滑杆也允许 `7、11、17…` 等容量；角度始终由 `360° / N` 精确计算，界面显示两位小数，因此圆环不会留下不等宽的最后一道缝。

## 视觉对照

- `ACTUAL ASSET`：使用内嵌的漫画培育仓缩略图，暴露真实素材的遮挡问题。
- `SCHEMATIC`：使用 CSS 简模，帮助判断纯轨道几何。
- 两种模式共享完全相同的尺寸、轴心、半径、角度与透视。
- 墙内竖轴只通过机械脊柱、接口槽和遮挡表达；没有圆盘、圆形转子或椭圆轨道线。
- Power Plant 墙体由 `68px` 缩至 `27px`，在 280px 侧栏中的宽度占比减少约 60%；仓体轴心同步左移并继续从墙体遮挡处伸出。

本轮不生成多角度仓体素材。角度方案胜出后，再围绕胜出角度制作 7–9 个方向帧或轻量 3D 仓体。

## 引导实验

每个标签都会重置为已知状态：

1. **巨构密集 36/10°**：观察大量空盘位是否足以表达超人类尺度，以及一次 10°切换是否仍可感知。
2. **暂定 12/30°**：观察 5 个可见盘位与明显的水平纵深位移是否达到当前期望。
3. **戏剧化 6/60°**：对照原 Q10 A，判断强烈动作是否以牺牲 Power Plant 尺度为代价。
